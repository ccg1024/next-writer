# Docs Guidelines

## Scope and Inheritance

- 本文件适用于 `docs/` 及其子目录。
- 继续遵守仓库根目录 `AGENTS.md`；本文件只补充文档读取和维护规则。
- 开始与项目规划、阶段实施、领域设计或用户配置有关的工作前，先阅读 `docs/index.md`，再选择相关文档。

## Document Responsibilities

- `project-plan.md` 是产品定位、长期目标、优先级和版本路线图的来源。
- `phase-*-plan.md` 描述对应阶段的目标、范围、模块拆分、依赖和验收标准。
- `phase-*-progress.md` 只记录当前实施事实、验证结果和剩余工作，不替代阶段计划或领域设计。
- 领域设计文档记录具体模块的稳定模型、不变量、边界和实现约束。
- 用户配置文档记录面向使用者的配置位置、格式、示例和兼容行为。
- 文档与当前代码、测试或用户明确要求冲突时，以代码、测试和明确要求为准，并同步修正文档中的过期内容。

## Reading Guidelines

- 先根据 `index.md` 中的分类定位文档，不要无目的地读取整个目录。
- 规划功能时读取整体规划、对应阶段计划和相关领域设计；检查当前状态时同时读取对应进度记录。
- 实现或修改行为时，以领域设计中的不变量和边界为约束，并用当前代码与测试验证文档结论。
- 不在多份文档中复制同一套详细规则；保留一个权威来源，其他文档使用相对链接引用。

## Adding and Maintaining Documents

- 新文档使用 kebab-case 文件名，并在开头提供清晰标题和用途说明。
- 新增文档时，必须在同一变更中将其加入 `docs/index.md` 的对应分类，并提供一句话职责说明。
- 重命名、移动或删除文档时，必须同步更新 `docs/index.md` 和仓库内指向该文档的链接。
- 只有文档形成独立、长期可维护的职责时才新建文件；补充或修正既有主题时优先更新现有文档。
- 进度类文档必须记录更新时间，并以当前提交、代码、测试和检查结果为依据；未验证内容应明确标记为待确认。
- 文档之间统一使用相对 Markdown 链接，确保仓库内浏览和重命名维护可控。
- 修改完成后检查索引覆盖情况、链接有效性和内容职责是否重复，并运行 Prettier 格式检查。
